# Monotonic terminal-close intent on the original continuation

A real paused CloseStep could previously be completed through ResetStep or ResetStreamStep because cleanup phase6 used the latest caller argument to decide whether to release its continuation. Both reset methods legitimately use the same phased cleanup and set closing themselves, so unconditional closing rejection would break valid reset retries.

The SAME fixed continuation now latches terminal close intent before admission can refuse. Close may promote a paused reset, and no reset may downgrade a started close. A single binding predicate covers owner/mode/dictionary validation and terminal intent across Begin, BeginStream, ResetStep and ResetStreamStep. Normal reset pauses remain resumable. Closing InputRequest and RawResult no longer expose further work or raw aliases; existing FeedInput and Step already reject closing. No new owner, ledger, callback or allocation was introduced.
